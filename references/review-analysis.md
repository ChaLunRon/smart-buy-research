# 评价分析方法论

这一步决定了最终结论的含金量。**检索只是采集，分析才是判断。** 采集到的原始内容中，商业污染比例在社交平台上可能超过一半，直接汇总等于把水军的意见当成用户共识。

## 一、区分三类样本

先给每条信息归类，再决定它的权重。

| 类型 | 特征 | 权重 |
|---|---|---|
| **证据型** | 带实拍/截图/视频，有具体场景，有时间跨度，主动提到缺点 | 高 |
| **观点型** | 纯文字主观感受，无证据，但叙述具体、有细节 | 中 |
| **噪音型** | 泛泛而谈、无细节、模板化、商业导流 | 剔除 |

**判断顺序**：先看有没有证据，再看有没有时间跨度，最后看有没有主动提及缺点。

**"主动提及缺点"是最强的可信信号。** 水军不会写缺点。一个内容里出现了具体的、对厂商不利的细节 —— 比如"这个牌子的客服确实难找，我等了三天" —— 这条内容的整体可信度大幅提升，因为欺骗性内容的成本会显著上升。

## 二、水军 / 恰饭内容识别

### 文本层信号

**必查项**
1. 通篇只有优点，缺点写成无关痛痒的小事（"就是包装有点简陋"）
2. 参数罗列密集但无个人实测，读起来像官方规格表
3. 出现"必入""闭眼冲""YYDS""绝绝子"等营销高频词，且密度异常
4. 对比只跟明显更差的竞品比（"比某品牌强多了"但不点名）
5. 结尾挂购买链接、优惠码、粉丝群
6. 有明确的"统一口径"痕迹：同一批账号用相同句式

**反直觉的识别点**
- 内容**过于完美**（排版、配图、文案都很专业）反而是信号 —— 真实用户的分享通常是随手拍的
- 优缺点比例失真 —— 真实用户的分享中，缺点往往占比不低，因为吐槽的动机比表扬强
- 提及竞品时用"某品牌"含糊带过，而对主推品牌则点名详细

### 账号层信号

| 信号 | 含义 |
|---|---|
| 历史内容全部同一品类/品牌 | 厂商号或垂直商单号 |
| 粉丝量与点赞量严重不匹配 | 买量 |
| 注册时间短、突然发爆款 | 为推广专门注册 |
| 发布频率异常高、间隙规律 | 内容农场 |
| 关注列表全是同品牌官方号 | 品牌矩阵 |

### 时间层信号（最易被忽略，但最有效）

**刷单和集中投放会在时间上留下痕迹。**

- 多条好评**集中在一两天内**发布 → 集中投放
- 发布时间呈现规律的"上班时间"分布 → 运营团队操作
- 长尾真实好评的时间分布是**自然分散**的
- 一款产品只有近期好评、之前完全无讨论 → 可能是新品，也可能是刚做过一轮投放

**操作方法**：在按时间排序的评价列表里，观察好评的时间密度。发现"一天内出现十几条措辞相似的好评"，整批剔除。

### 图片层信号
- 多篇内容的配图角度、背景、桌上物品高度相似 → 同一次拍摄分发
- 图片过于精美、有专业布光 → 商业摄影
- 有明确品牌露出且构图讲究 → 商单
- 随手拍、环境杂乱、有生活痕迹 → 大概率真实

## 三、好评的读法

**绝对数量无意义，雷同度才有意义。**

好评的核心价值不在"说它好"，而在：
- **好在哪里** —— 如果一百条好评都只说"质量好""性价比高"而不说具体好在哪，这些好评没有信息量
- **有没有无效好评集群** —— 集群存在本身就是对品牌的负面判断（说明厂商在控评，侧面反映对真实口碑不自信）
- **好评提及的优点是否与用户需求匹配** —— 所有人夸它续航，但用户要的是便携，那这些好评对本次决策无用

**关键判断**：如果一个产品的好评**高度集中在营销话术上**，而差评**高度集中在具体功能缺陷上**，那么真实产品力应该以后者为准。

## 四、差评的读法（最重要）

**单条差评是噪音，重复出现的差评是设计缺陷。**

### 差评的信息提取三要素

| 要素 | 提取内容 | 用途 |
|---|---|---|
| **具体现象** | 到底坏了什么、哪里不好用 | 区分主观不满与客观缺陷 |
| **使用时长** | 买来多久后出现 | 区分"初期品控"与"设计寿命" |
| **证据强度** | 有无图片、视频、维保记录 | 判定可信度 |

### 差评分类与处理

**A 类 — 产品缺陷型**
- 具体功能失效、硬件损坏、性能不达标
- → 记录，若多条重复则升级为核心结论依据

**B 类 — 服务物流型**
- 快递慢、包装破损、客服态度
- → 与产品本身无关，单独归类，用来判断渠道而非产品

**C 类 — 期望落差型**
- "没有想象中好""不值这个价"
- → 无具体信息，权重低，但若大量出现说明定价或宣传有问题

**D 类 — 用户误用型**
- 不会用、买错型号、不匹配自己设备
- → 剔除，但可以转化为"选购提醒"输出给用户

### 长测差评的特殊价值

**"用了半年"、"一年后"、"用坏了"这类内容几乎不可能是水军。** 水军的投放周期通常集中在发售期，不会持续半年。因此：

- 长测内容的可信度远高于开箱内容
- 长测差评能暴露**设计寿命问题**（塑料件老化、电池衰减、涂层脱落），这类问题在开箱评测里根本看不出来
- 优先检索 `{型号} 一年后` `{型号} 长期使用` `{型号} 用多久坏`

### 差评率的正确计算

**错误做法**：比较差评的绝对数量。卖得多的差评自然多。

**正确做法**：看**同一问题在讨论中的出现频率**，以及它在总讨论中的占比。

判断框架：
1. 这个缺点在**多少个不同来源**被独立提到？（来源数比条数重要）
2. 提的人**是不是同一批账号**？（排除刷差评）
3. 这个缺点**是否影响用户的核心场景**？（无关紧要的缺点不否决产品）
4. 这个缺点是**批次性问题还是设计性问题**？（批次问题可能已修复）

## 五、交叉验证

### 验证规则

| 结论类型 | 最低独立来源 | 附加要求 |
|---|---|---|
| 致命缺陷（安全隐患、批量故障） | 3 个 | 至少 1 个带证据 |
| 产品级缺陷 | 2 个 | 来自不同平台 |
| 品牌级判断 | 2 个 | 优先采用投诉平台数据 |
| 主观偏好 | 1 个 | 标注为主观 |

### "独立来源"的定义

两条内容如果不是**独立产生**的，只算一个来源：
- 同一作者的多个平台账号 → 1 个来源
- 互相引用、转载的关系 → 1 个来源
- 同一营销矩阵的账号 → 1 个来源

### 反例检索（必做）

对要写入结论的每个关键判断，**主动去搜反例**。搜"XX 好"会强化既有印象，搜"XX 有没有人说好"才能真正检验。

具体做法：对每条准备写入的结论，问一句"**如果这条是错的，网上会有什么样的内容？**"然后去搜那个内容。

## 六、常见认知偏误（自查清单）

分析完成后，对照以下清单自查：

| 偏误 | 表现 | 纠正 |
|---|---|---|
| **声量偏差** | 把小众平台的高声量当主流共识 | 检查该平台的用户画像是否匹配目标用户 |
| **幸存者偏差** | 只看到满意用户的分享，不知道沉默的退货者 | 主动去找投诉、退货、二手转让的信息 |
| **时间衰减** | 用三年前的评价判断当前批次 | 优先近一年信息，标注批次差异 |
| **高赞权威** | 把高赞等同于正确 | 高赞只说明引发了情绪共鸣 |
| **专业错配** | 用极客的挑剔标准否决普通用户的好选择 | 判断缺点是否影响用户真实场景 |
| **新品陷阱** | 把"没有差评"当成"没有缺点" | 新品标注"缺乏长期验证" |
| **确认偏误** | 搜到支持自己初步判断的内容就停止 | 强制检索反例 |
| **单一权威** | 依赖一个看似专业的深度长文 | 至少两个独立来源 |

## 七、从差评生成"选购提醒"

差评分析的最终产出不只是"这个产品好不好"，还应该转化成**用户能用的判断标准**。

转化方法：把重复出现的差评，改写成"买这类产品时要检查什么"。

**示例：**
- 差评规律："XX 耳机戴一小时耳朵疼"
- → 输出："这类耳机要注意耳塞尺寸和腔体重量，佩戴超过一小时会有压迫感，建议线下试戴或选择轻量款"

- 差评规律："XX 笔记本用一年后电池鼓包"
- → 输出："这款机型有电池老化后鼓包的反馈，尽量选择官方延保或注意散热使用"

**这一步产出的价值往往高于产品推荐本身** —— 因为选购提醒具有跨品牌的通用性。

## 八、必要性分析框架（v2 新增）

在做任何产品调研之前，先判断"该不该买"。这一步的投入产出比是全流程最高的——劝退一次能省 100% 的钱，而选型优化最多省 20%。

### 三类需求的处理

| 需求性质 | 特征 | 处理 |
|---|---|---|
| **解决型** | 现有方案不能用/不存在，有具体痛点 | 直接进入调研，不做拷问 |
| **改善型** | 现有方案能用，只是想要更好 | **必须拷问**：改善的幅度值这个钱吗 |
| **情绪型** | 想要而非需要，受种草/大促/他人影响 | **重点拷问**：这是谁的欲望 |

### 拷问的三个问题

1. **现有方案是什么？它哪里不够用？**
   - 答不上具体痛点 → 大概率不需要
   - 痛点模糊（"就是想换个新的"）→ 情绪驱动

2. **不买会怎样？**
   - "没什么影响" → 不需要
   - "会一直不舒服/不方便" → 有真实痛点

3. **同类需求你是第几次想买？**
   - 反复想买但一直没下手 → 通常是伪需求
   - 明确等某个条件（坏了/不够用了）→ 真实需求

### 伪需求高发品类速查

| 品类 | 伪需求特征 | 拷问切入点 |
|---|---|---|
| 保健品 | 健康人补充自合成营养素 | "体检有相关指标异常吗" |
| 改善型小家电 | 冲动购买、闲置率高 | "一周会用几次" |
| 升级换代数码 | 想要新而非需要新 | "现有设备哪里不够用" |
| 健身器材 | 依赖"未来的决心" | "过去半年你去过几次健身房" |
| 学习工具 | 买工具代替学习本身 | "你打算用它做什么具体的事" |
| 大促凑单 | 为满减而买 | "这件东西如果单独卖你还会买吗" |
| 潮玩收藏 | 纯粹情绪价值 | 不劝退，但提示预算边界 |

### 判断准则：参考过去行为，不参考未来决心

**"我应该会经常用"是最不可靠的假设。** 人对未来的自己有系统性乐观偏差。

正确的参考点是**已经发生的行为**：
- 不是"我打算每周做饭"，而是"过去一个月我做了几次饭"
- 不是"我会每天健身"，而是"我上次健身是什么时候"

### 输出纪律

- **劝退要克制。** 用户明确说"我知道我需要"时立刻停止拷问
- **劝退要给理由和金额。** "不买能省 300 块，而且你现有那个还能用两年"
- **不确定时给缓冲建议。** "加购物车放 3 天，如果三天后还想要再买"——大量冲动消费会在等待期消退
- **不替用户做道德判断。** 买潮玩、买收藏不是浪费，只要用户清楚自己在为什么付费
