## 零、两个独立难题：找社区 ≠ 读社区

**这是实测算出来的教训，必须分开处理。**

| 难题 | 表现 | 对策 |
|---|---|---|
| **找社区** | 不知道某品类有没有专业社区 | 搜 `{品类} 论坛` `{品类} 哪个网站专业`；查 sources-map 第五节对照表 |
| **读社区** | 知道社区名字，但页面读不到内容 | 本文件下面的方案一~五 |

**纪律**：
- **"我找到了专业社区"≠"我读到了专业社区的内容"**，绝不在结论里把两者混为一谈
- 只读到摘要时，结论里标注 **（仅摘要）**
- 摘要只能用于判断方向，不能用来支撑具体结论

## 一、⭐ 无头浏览器（2026-09 实测，首选）

**这一节是实测结论，优先于下面的爬虫方案。** 很多"读不到"其实只是少了真实浏览器。

### 结论速查表（实测）

| 平台 | 纯 HTTP 直接请求 | 真实浏览器 | 免登录可读内容 |
|---|---|---|---|
| **B站** | 视频信息 API ✅；搜索/评论 ❌（需 WBI 签名） | ✅ | **搜索页、视频页、评论**（见方案二，API 更省资源） |
| **NGA** | ❌ 403「访客不能直接访问」 | ✅ **完全可读** | **首页、全部公开版面、帖子** |
| **微信公众号** | ✅ **直连可读正文**（见方案三） | ✅ | **单篇文章全文** |
| **小红书** | ❌ 302 跳登录 | ❌ **IP 级风控拦截** | **本机网络下不可读**（见下方说明） |

### 怎么用

```bash
# 1. 装（一次性）
#    注意：本机环境可能不允许 -g 全局安装，可改为装到当前目录
npm i agent-browser
npx agent-browser install          # 下载配套 Chrome（约 196MB / 205,149,043 字节）

# 2. 开页面
npx agent-browser open <url>
npx agent-browser wait --load networkidle
npx agent-browser get text body          # 读正文
npx agent-browser screenshot out.png     # 或截图给人看
npx agent-browser close                  # 收尾必须关
```

**要点**：
- 每次页面变化后要重新 `snapshot`，ref（`@eN`）会失效
- 用 `find placeholder "搜索" type "关键词"` 操作搜索框；**搜索框有时在屏幕外，先 `scroll down` 再操作**
- 直接拼搜索 URL 比点搜索框可靠得多，例：
  - B站：`https://search.bilibili.com/all?keyword={关键词}`
  - 小红书：`https://www.xiaohongshu.com/search_result?keyword={关键词}`
- **Chrome 下载慢时换镜像**（实测 npmmirror 比 Google CDN 快 12 倍）：
  `https://registry.npmmirror.com/-/binary/chrome-for-testing/<版本>/win64/chrome-win64.zip`
- 已有 Chrome 时用 `--executable-path <路径>` 或环境变量 `AGENT_BROWSER_EXECUTABLE_PATH`
  **⚠️ 坑：daemon 已在运行时 `--executable-path` 会被忽略，必须先 `close --all`**

### 各平台实测细节

**✅ NGA —— 完全可读（最大收获）**

- 纯请求返回 403「访客不能直接访问」，`read.php?tid=` 返回 403「未登录」
- **但真实浏览器打开 `https://bbs.nga.cn/` 完全正常**：版面列表、在线人数、帖子全部可见
- 与商品调研最相关的版面：**PC硬件配置 / 装机讨论 / 消费电子IT新闻 / 消费踩坑避雷 / 手机研究所 / 外设硬件**

**✅ B站 —— 搜索与视频页可读**

- 搜索页 `https://search.bilibili.com/all?keyword=` 免登录返回完整结果列表（标题/UP主/播放量/时长/日期）
- 视频页可读标题、播放/点赞数、弹幕、字幕作者、相关推荐
- 会弹登录浮层，但**不影响读取内容**，忽略即可
- 走 API 更省资源（见方案二）

**✅ 微信公众号 —— 直连就能读（结论已更正）**

- 见方案三。**不需要爬虫，不需要登录。**

**❌ 小红书 —— 本机网络下不可读（诚实结论）**

- 桌面版 `/`、`/explore`：302 跳登录页
- 搜索页：**即使真实浏览器也会被拦**，落到 `website-login/error`：
  ```
  error_code=300012
  error_msg=IP存在风险，请切换可靠网络环境后重试
  rejectUrl=edith.xiaohongshu.com/api/sns/web/v1/login/activate
  ```
- **这是 IP/网络环境级的风控判定，不是登录问题**，换 UA、换入口、用浏览器都无效
- 网上"小红书网页版完全免登录"的说法**在本机网络环境下不成立**，不要照抄
- **只能靠**：① 换网络环境；② 用户截图/贴链接协作；③ 登录态（有账号风险）

## 二、B站 API（比浏览器更省资源）

**免登录可用的接口：**

| 用途 | 接口 | 说明 |
|---|---|---|
| 视频信息 | `api.bilibili.com/x/web-interface/view?bvid={BV号}` | ✅ 标题/UP主/播放/点赞/评论数 |
| WBI 密钥 | `api.bilibili.com/x/web-interface/nav` | ✅ 返回 `img_key`/`sub_key`（`code=-101` 未登录但密钥照给） |
| 评论 | `api.bilibili.com/x/v2/reply/wbi/main?...` | ⚠️ **必须 WBI 签名**，否则返回 `-352` |
| 搜索 | `api.bilibili.com/x/web-interface/search/type?...` | ❌ 无 Cookie 时 `-412` 限流，**改用浏览器搜索页** |

**WBI 签名要点**（这就是"老爬虫全挂"的原因）：
- 从 nav 取 `img_key` + `sub_key`，拼接后按固定 64 位混淆表重排，取前 32 位得 `mixin_key`
- 参数按 key 排序 → 过滤 `!'()*` → urlencode → 加 `wts=当前秒级时间戳`
- `w_rid = md5(规范化查询串 + mixin_key)`
- 请求头需带 `Referer: https://www.bilibili.com/video/{BV号}`

**⚠️ 纪律**：`-412` 是限流信号，**必须**随机 sleep 0.5~1.5s、带真实 Referer、失败重试不超过 3 次。

## 三、微信公众号（结论已更正：直连可读）

**原先"搜狗微信搜索"的说法已作废** —— `weixin.sogou.com` 已于 2021-09 停止服务，不要再用。

### ✅ 正确做法：单篇文章直连即可

公开文章链接（`https://mp.weixin.qq.com/s/<id>`）**免登录、免 Cookie、免爬虫**，带浏览器 UA 普通请求就能拿到全文。

**实测**（3 篇真实文章全部成功）：

```
标题: 聊一款配色新奇的笔记本
公众号: 奥拉猪汪
发布: 2018-01-06 10:02:37
图片数: 6
正文: 约 2000 字完整提取 ✅
```

**现成脚本**：`scripts/fetch_wechat_article.py`

```bash
python scripts/fetch_wechat_article.py "https://mp.weixin.qq.com/s/xxxxx"
python scripts/fetch_wechat_article.py "<url>" --json out.json
```

**限制与风控**：
- 需要**已知链接**。它不解决"我要按关键词搜公众号"这个问题
- robots.txt 禁止爬虫，**高频请求会触发验证码 → 必须低频**
- 命中 `环境异常 / 完成验证 / 参数错误 / 该内容已被发布者删除` 说明被拦或文章失效，脚本会显式报出来
- 单篇失败时用请求头补 `Referer: https://mp.weixin.qq.com/` 再试

### 按关键词/按公众号批量获取（成本高，按需）

| 项目 | 能力 | 门槛 |
|---|---|---|
| `qbu11/wechat-article-spider` | `login`/`search`/`scrape`，按公众号名、页数、天数导出正文 | **需注册一个自己的公众号账号**（免费但要手机验证） |
| `ghh1251/wechat_articles_spider` | 按关键词在历史文章中检索并加权排序 | 同上 |
| wechat-article-exporter | 借微信公众平台后台接口批量导出 | 同上 |
| 新榜等数据平台 | 结构化 API | 付费 |
| `we-mp-rss` | 微信读书中转成 RSS，长期订阅一批号 | 自建 |

**纪律**：需要公众号账号的方案**务必用不重要的小号**，别拿主号去登。

### 找链接的办法

1. 搜索引擎 `site:mp.weixin.qq.com {关键词}`
2. 垂直社区里别人贴的转载链接（**实测最有效**：很多优质公众号文章会被论坛/知乎/贴吧转载并附原文链接）
3. 让用户直接从微信转发链接过来（用户协作，零风险最快）

| 平台 | 关键词搜索 | 指定帖子 | 二级评论 | 创作者主页 |

## 八、电商平台（京东/淘宝/拼多多）的反爬与比价

**这一节与 `price-and-channel.md` 配合使用。**

### 反爬情况

| 平台 | 反爬强度 | 常见表现 |
|---|---|---|
| 京东 | 中 | 价格可直接读到；"问大家"需登录；商品页偶发拦截 |
| 淘宝/天猫 | **高** | 商品页、评价页基本需要登录；滑块验证频繁 |
| 拼多多 | **高** | 网页版功能残缺，主要走 App；"问大家"与评价需登录 |

**所以：电商平台优先走"用户截图协作"，而不是硬爬。**

### 可用的开源方案（GitHub 调研结果）

**方案一：maishou 比价工具（覆盖最广）**

- **GitHub: `aahl/skills` 的 `maishou` skill** —— 约 153 stars，2026-07 更新
- 覆盖：淘宝/天猫、京东、拼多多、苏宁、唯品会、考拉、抖音、快手、1688
- 命令：`uv run scripts/main.py search --source=0 --keyword='{关键词}'`
- `source` 参数：`0` 全部 / `1` 淘宝天猫 / `2` 京东 / `3` 拼多多 / `4` 苏宁 / `5` 唯品会 / `6` 考拉 / `7` 抖音 / `8` 快手 / `10` 1688
- 依赖：Python ≥3.11、uv、aiohttp
- **⚠️ 风险**：依赖**非官方第三方 API**（appapi.maishou88.com），安全审计未全绿。**使用前必须告知用户并取得同意**，不要静默调用。

**方案二：PriceLens（本地优先，隐私最好）**

- **GitHub: `wuliao00/PriceLens`** —— MIT 开源，双端（Android + Windows Electron）
- 能力：京东/淘宝/拼多多商品页自动读价、历史价格曲线、优惠券一键复制、B站翻车/推荐视频识别
- 兜底源：识货（shihuo.cn）、什么值得买、慢慢买、购物党
- **注意这是客户端工具，需要用户自己装**

**方案三：慢慢买历史价格（有逆向参考）**

- **GitHub: `PPsteven/manmanbuy_js_crack`** —— 慢慢买比价爬虫的 JS 逆向破解记录
- 价值：聚合淘宝/京东/天猫/拼多多历史价格，识别"先涨后降"
- 接口形态：`POST http://tool.manmanbuy.com/api.ashx`，参数含 `method=getHistoryTrend`、商品链接、时间戳、token
- **注意**：该项目价值在于**记录了破解思路**，不是开箱即用

**方案四：xiaxiayouhui-deals（只读 API，最干净）**

- 服务地址 `https://xiaxiayouhui.xyz/api/skill/v1/*`，MIT 开源，有 ICP 备案
- 接口：`compare`（跨平台比价）、`coupon`（找券）、`parse-link`（链接口令解析）、`daily-deals`（今日好价）

### 使用顺序（电商比价）

```
用户截图（最可靠，首选）
  ↓
无头浏览器打开商品页（京东较可行；淘宝/拼多多多半要登录）
  ↓
PriceLens / 比价客户端（用户自己装，隐私好）
  ↓
maishou / xiaxiayouhui（第三方 API，需用户同意）
  ↓
慢慢买逆向方案（技术门槛高，仅在必要时）
```

**核心纪律：电商数据的可信度优先级是"用户自己看到的" > "工具抓到的"。** 券和补贴这类会变的信息，永远让用户自己在页面上确认。
