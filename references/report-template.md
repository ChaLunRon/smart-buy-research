# 调研报告模板（v2）

**仅在用户明确要求生成报告文件时使用。** 默认输出是对话内的简洁结论。

输出格式：Markdown（默认）或 HTML（用户要求更好看的呈现时）。
输出位置：当前工作目录，文件名格式 `商品调研-{品类}-{YYYYMMDD}.md`。

## 写作要求

1. **"要不要买"必须放最前面。** 如果结论是"不建议买"，整份报告的重心就要转向劝退，不要还写一大堆选品对比。
2. **首推必须唯一。** 不要给三个"都很推荐"的选项，那是没做判断。
3. **必须有不推荐项。** 一份没有排除任何选项的报告，说明调研没有收敛。
4. **短板必须诚实。** 首推产品也要写清缺点，否则用户会觉得自己被推销了。
5. **证据要可追溯。** 每条关键判断挂来源类型和时间，不写"网上都说"。
6. **不做担保。** 用"核验到/未核验到"的客观陈述，不写"质量有保障""放心买"。
7. **区分事实与判断。** 事实写"多条反馈提到 X"，判断写"据此判断 Y"，两者不混写。
8. **每平台最多一条链接。** 不要甩一堆链接制造新的选择困难。
9. **未执行的步骤要说明。** 例如风格类商品未做资质核验，要写出来并说明原因，而不是留空。
10. **来源类型必须标注。** 每条关键论据后标出信源类别（专业垂直社区 / 社交平台 / 电商评价 / 国际独立源 / 官方平台）。**头部结果若集中在单一平台（尤其被列入垃圾信源黑名单的平台），必须重搜换源后再写。**
11. **垂直社区必须在报告里点名。** 如果该品类存在专业垂直社区，报告要写明访问了哪个、采集了什么，而不是只列大平台。

## 与默认输出的关系（重要）

本模板**只在用户明确索取报告文件时**启用。用户没要求时，一律走 SKILL.md 里的「输出规则：默认极简」四段式，**不要**把这份模板的章节结构搬到对话里。

判断标准：

| 用户的话 | 该做什么 |
|---|---|
| "推荐一个…" / "买哪个" / "值不值" | 默认极简四段式（≤400 字） |
| "详细说说" / "给个对比" | 适度展开，可以上表格，但仍不生成文件 |
| "出一份报告" / "整理成文档" / "给我文件" | 启用本模板，生成 `.md` 或 `.html` 文件 |

报告生成后，**对话回复本身仍然要遵守极简规则**——回复里只放结论摘要，详细内容进文件。
